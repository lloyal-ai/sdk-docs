<div class="reference-grid">
<a href="#floors">Node <span class="out">&gt;=24</span></a>
<a href="#floors">Memory <span class="out">16 GB</span></a>
<a href="#floors">Weights <span class="out">2.6 GB</span></a>

<p><strong>Node 24 or newer</strong>, declared by both the CLI and every scaffolded project. <strong>16 GB of RAM or unified memory</strong> is the working recommendation: the recommended trunk model is 2.6 GB of weights, the <code>research</code> template adds a 630 MB reranker, and the remainder covers KV at the recommended 32k context plus the OS and whichever surface is running.</p>
<p><strong>Concurrent agents do not multiply this.</strong> They share one context, so cost tracks KV <em>fullness</em>, not agent count — four agents is not four times the model.</p>

<div class="section-kicker">Retrieval</div>
<h2>Scoring</h2>
<p>One cross-encoder serves four distinct roles. Conflating the three queries in play — the per-call tool query, the per-agent task, and the original research query — produces wrong scores.</p>
<p class="path-label">packages/agents/src/source.ts</p>
<pre><code>interface EntailmentScorer {
  scoreEntailmentBatch(texts: string[]): Promise&lt;number[]&gt;;
  scoreRelevanceBatch(texts: string[], localQuery: string): Promise&lt;number[]&gt;;
  scoreSimilarityBatch(reference: string, texts: string[]): Promise&lt;number[]&gt;;
  shouldProceed(score: number): boolean;
}

interface ScorerReranker {
  scoreBatch(query: string, texts: string[]): Promise&lt;number[]&gt;;
}</code></pre>
<div class="reference-grid">
<a href="#scoring">scoreEntailmentBatch <span class="out">against the original query</span></a>
<a href="#scoring">scoreRelevanceBatch <span class="out">min(local, original) — exploit</span></a>
<a href="#scoring">scoreSimilarityBatch <span class="out">echo detection at delegation</span></a>
<a href="#scoring">shouldProceed <span class="out">floor gate</span></a>
</div>
<p>The score is a <strong>logit-diff</strong> — <code>logit(yes) − logit(no)</code>, unbounded, sign carries meaning. <code>Source._entailmentFloor</code> defaults to <strong>0</strong>: a hit passes when the cross-encoder leans yes. Raise it for noise-heavy corpora, lower it for sparse ones.</p>
<p><code>Source</code> is abstract over <code>&lt;TCtx, TChunk&gt;</code> with <code>name</code>, <code>get tools(): Tool[]</code>, <code>createScorer(originalQuery)</code>, <code>promptData(): Record&lt;string, unknown&gt;</code>, and <code>getChunks(): TChunk[]</code>. <code>promptData()</code> is what the per-spawn skill template reads, so an agent learns what kind of source it is holding before it searches.</p>
</section>

<section class="architecture wrap">
<div class="section-kicker">Authority</div>
<h2>Consent and protected tools</h2>
<p>The gate for consequential actions runs at DISPATCH, in the agent runtime — below any application or UI code that could misreport it.</p>
<p class="path-label">packages/agents/src/grant-store.ts · context.ts</p>
<pre><code>interface GrantStore {
  has(toolName: string): Operation&lt;boolean&gt;;
  grant(toolName: string): Operation&lt;void&gt;;
  revoke(toolName: string): Operation&lt;void&gt;;
}

GrantStoreCtx  // createContext&lt;GrantStore&gt;('lloyal.grantStore')</code></pre>
<p><strong>Fail-closed.</strong> A tool marked <code>protected</code> is denied unless the session holds a grant. No grant store configured means every protected tool is denied. Credentials never enter the model's context — the model can trigger a gated call, never see or replay the secret.</p>
</section>

<div class="section-kicker">Diagnosis</div>
<h2>Traces</h2>
<p>Pass a writer to <code>initAgents</code> to capture the inference graph as newline-delimited JSON. With none passed, <code>NullTraceWriter</code> makes every trace call a no-op at zero cost.</p>
<p class="path-label">packages/agents/src/trace-types.ts — the full event union</p>
<div class="reference-grid">
<a href="#traces">scope:open / close <span class="out">named boundaries + duration</span></a>
<a href="#traces">prompt:format <span class="out">the exact prompt the model saw</span></a>
<a href="#traces">agent:turn <span class="out">raw output, parsed content, tool calls</span></a>
<a href="#traces">tool:dispatch <span class="out">args, toolkit position, explore, pressure</span></a>
<a href="#traces">tool:result / error / retry <span class="out">prefill tokens, duration</span></a>
<a href="#traces">tool:authReject <span class="out">protected-tool denial + lineage</span></a>
<a href="#traces">pool:open / close / agentDrop <span class="out">pressure, findings, drop reason</span></a>
<a href="#traces">pool:recovery* <span class="out">extraction diagnostics</span></a>
<a href="#traces">spine:extend <span class="out">orchestrator extensions</span></a>
<a href="#traces">branch:create / prefill / prune <span class="out">KV lifecycle</span></a>
<a href="#traces">entailment:* <span class="out">scoring decisions at each boundary</span></a>
</div>
<p>Events form a tree via <code>parentTraceId</code>; the <code>TraceParent</code> context connects inner pools to the tool dispatch that spawned them with no manual wiring.</p>
