    <article class="article"><h1 id="start-here">Start here</h1>
<h2 id="the-decision-hierarchy">The decision hierarchy</h2>
<p>A policy decision sits inside a larger execution stack:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>Effection scope
└── AgentPool                              owns the live execution
    ├── BranchStore                        accounts for inference state
    ├── ContextPressure                    freezes the current resource facts
    ├── AgentPolicy                        chooses the next behavioural action
    └── Pool mechanics                     safely apply that action
        ├── decode and commit
        ├── Tool dispatch and settlement
        ├── recovery
        └── branch pruning
</code></pre></div><p>Read it from the outside in:</p>
<ol>
<li><strong>Effection decides whether the pool still has an owner.</strong></li>
<li><strong>BranchStore records what live inference state exists.</strong></li>
<li><strong>ContextPressure presents a stable snapshot of what remains.</strong></li>
<li><strong>AgentPolicy interprets the situation.</strong></li>
<li><strong>AgentPool performs the decision without violating runtime safety.</strong></li>
</ol>
<p>Policy never owns the Session, schedules native decode, or prunes branches directly.</p>
<hr/>
<h2 id="the-three-questions">The three questions</h2>
<h3 id="1-does-this-work-still-have-an-owner">1. Does this work still have an owner?</h3>
<p>That is a <strong>structured-concurrency</strong> question.</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>Session released
    ↓
harness scope halts
    ↓
pool and all child work unwind
</code></pre></div><p>AgentPolicy is not consulted to preserve work whose owner has disappeared.</p>
<h3 id="2-should-this-agent-continue">2. Should this Agent continue?</h3>
<p>That is a <strong>policy</strong> question.</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>pool remains alive
    ↓
Agent reaches a decision boundary
    ↓
policy chooses continue, nudge, retry, return, stop, or recover
</code></pre></div><p>The Agent may stop while its siblings and parent pool continue.</p>
<h3 id="3-can-the-requested-action-be-performed-safely">3. Can the requested action be performed safely?</h3>
<p>That is an <strong>AgentPool</strong> question.</p>
<p>Policy can request recovery or provide a preferred report budget. The pool computes what fits, enforces grammar and token limits, and protects the native context.</p>
<hr/>
<h2 id="the-five-rules">The five rules</h2>
<ol>
<li><strong>Policy is a rulebook, not a scheduler.</strong></li>
<li><strong>Pressure is a snapshot, not a mutable global gauge.</strong></li>
<li><strong>The soft limit closes new work.</strong></li>
<li><strong>The hard limit prevents unsafe continuation and bounds recovery.</strong></li>
<li><strong>Policy requests recovery; the pool makes it mechanically safe.</strong></li>
</ol>
<hr/>
<h2 id="the-two-axes">The two axes</h2>
<p>Pressure affects both strategy and lifecycle, but these are not the same decision.</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>strategy:
explore ───────────────────────────────→ exploit

lifecycle:
work ─────────────→ report ────────────→ recover or prune
</code></pre></div><p>An Agent can exploit while still healthy.</p>
<p><code>shouldExplore() === false</code> does not mean the Agent should stop.</p>

<h1 id="1-ownership-boundary">1. Ownership boundary</h1>
<h2 id="scope-termination-and-agent-termination">Scope termination and Agent termination</h2>
<p>These events can look similar in a UI but have different meanings.</p>
<h3 id="the-owner-disappears">The owner disappears</h3>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>browser disconnects
        ↓
Session is released
        ↓
harness scope halts
        ↓
pool, Tools, subscriptions, and child Operations unwind
</code></pre></div><p>Effection owns this behaviour.</p>
<p>There is no longer a live parent waiting for the result.</p>
<h3 id="one-agent-stops-inside-a-live-pool">One Agent stops inside a live pool</h3>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>pool remains alive
        ↓
policy decides this Agent should stop
        ↓
its branch remains temporarily available
        ↓
recovery may extract useful findings
        ↓
branch is pruned
        ↓
siblings continue
</code></pre></div><p>AgentPolicy and AgentPool own this behaviour.</p>
<p>The result may still be valuable to the active query.</p>
<blockquote>
<p><strong>Effection halt ends an ownership scope. Policy termination changes an Agent’s lifecycle inside a scope that still exists.</strong></p>
</blockquote>
<p>Do not use policy hooks to imitate scope cancellation. Do not treat Session cancellation as an ordinary policy stop.</p>
<hr/>
<h1 id="2-the-decision-stack">2. The decision stack</h1>
<h2 id="the-four-layer-decision-path">The four-layer decision path</h2>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>BranchStore
    owns branches and accounts for live KV cells
        ↓
ContextPressure
    freezes a consistent view of what remains
        ↓
AgentPolicy
    maps Agent state and pressure to an action
        ↓
AgentPool
    executes the action, batches native work, and preserves safety
</code></pre></div><h3 id="branchstore-accounts">BranchStore accounts</h3>
<p>BranchStore tracks:</p>
<ul>
<li>shared prefixes;</li>
<li>private branch suffixes;</li>
<li>branch positions;</li>
<li>cells consumed by generation and prefill;</li>
<li>cells reclaimed by pruning.</li>
</ul>
<p>It does not decide whether the work is useful.</p>
<h3 id="contextpressure-observes">ContextPressure observes</h3>
<p><code>ContextPressure</code> derives stable facts for one decision boundary:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="nx">remaining</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">nCtx</span><span class="w"> </span><span class="o">-</span><span class="w"> </span><span class="nx">cellsUsed</span><span class="p">;</span>
<span class="nx">headroom</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">remaining</span><span class="w"> </span><span class="o">-</span><span class="w"> </span><span class="nx">softLimit</span><span class="p">;</span>
<span class="nx">critical</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">remaining</span><span class="w"> </span><span class="o">&lt;</span><span class="w"> </span><span class="nx">hardLimit</span><span class="p">;</span>
<span class="nx">percentAvailable</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">round</span><span class="p">(</span><span class="nx">remaining</span><span class="w"> </span><span class="o">/</span><span class="w"> </span><span class="nx">nCtx</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="mf">100</span><span class="p">);</span>
</code></pre></div><p>It does not nudge, kill, retry, or recover an Agent.</p>
<h3 id="agentpolicy-decides">AgentPolicy decides</h3>
<p>Policy receives some combination of:</p>
<ul>
<li>the Agent;</li>
<li>parsed model output;</li>
<li>a pending Tool result;</li>
<li>a pressure snapshot;</li>
<li>pool configuration;</li>
<li>policy state such as elapsed time.</li>
</ul>
<p>It returns a declarative action.</p>
<h3 id="agentpool-enforces">AgentPool enforces</h3>
<p>The pool:</p>
<ul>
<li>advances branches;</li>
<li>commits sampled tokens;</li>
<li>dispatches Tools;</li>
<li>admits or defers prefill;</li>
<li>forces terminal grammar during recovery;</li>
<li>clamps report budgets to what fits;</li>
<li>salvages partial reports;</li>
<li>prunes branches;</li>
<li>emits lifecycle events.</li>
</ul>
<p>Policy never bypasses those mechanics.</p>
<hr/>
<h2 id="pressure-is-a-photograph-not-a-live-gauge">Pressure is a photograph, not a live gauge</h2>
<p>The pool freezes <code>ContextPressure</code> at phase boundaries.</p>
<p>Every policy decision in that phase sees the same baseline.</p>
<p>Without a snapshot:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>Agent A evaluated first
    sees more space

Agent B evaluated later
    sees less space
</code></pre></div><p>The same cohort could behave differently merely because an array was iterated in another order.</p>
<p>Instead:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>phase begins
    ↓
freeze one pressure snapshot
    ↓
all policy decisions use that snapshot
    ↓
batch native mutations
    ↓
next phase receives a new snapshot
</code></pre></div><p>SETTLE maintains local admission accounting while building its batch because native <code>cellsUsed</code> updates only when the prefill is committed.</p>
<blockquote>
<p><strong>Reason from the supplied snapshot. Do not poll native pressure inside a hook and do not mutate it.</strong></p>
</blockquote>
<hr/>
<h2 id="every-agent-spends-live-attention-budget">Every Agent spends live-attention budget</h2>
<p>Each Agent spends from the Session’s finite live-attention budget through:</p>
<ul>
<li>generated tokens;</li>
<li>Tool-result prefill;</li>
<li>recovery prompts and reports;</li>
<li>nested Agent work;</li>
<li>private suffixes across sibling branches.</li>
</ul>
<p>Shared prefixes are amortised, but new private tokens still occupy live cells.</p>
<p>Pressure is not a static prompt-length limit. It changes as the cohort works.</p>
<hr/>
<h1 id="3-pressure-boundaries">3. Pressure boundaries</h1>
<h2 id="the-two-limits-are-not-symmetric">The two limits are not symmetric</h2>
<p>The most common mistake is treating <code>softLimit</code> and <code>hardLimit</code> as stronger and weaker forms of the same cutoff.</p>
<p>They have different jobs.</p>
<h2 id="soft-limit-the-new-work-boundary">Soft limit: the new-work boundary</h2>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="nx">headroom</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">remaining</span><span class="w"> </span><span class="o">-</span><span class="w"> </span><span class="nx">softLimit</span><span class="p">;</span>
</code></pre></div><p>When <code>headroom &gt; 0</code>, ordinary new work may be admitted.</p>
<p>When <code>headroom &lt;= 0</code>, the system should contract:</p>
<ul>
<li>do not spawn new research Agents;</li>
<li>defer oversized ordinary Tool results;</li>
<li>nudge non-terminal calls towards reporting;</li>
<li>narrow from exploration towards exploitation;</li>
<li>preserve capacity for downstream work and recovery.</li>
</ul>
<p>The soft limit is advisory.</p>
<p>Crossing it does not automatically make decode unsafe.</p>
<h2 id="hard-limit-the-safety-and-recovery-boundary">Hard limit: the safety and recovery boundary</h2>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="nx">critical</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="nx">remaining</span><span class="w"> </span><span class="o">&lt;</span><span class="w"> </span><span class="nx">hardLimit</span><span class="p">;</span>
</code></pre></div><p>The hard limit is mechanical:</p>
<ul>
<li>an ordinary Agent must not continue into another unsafe decode;</li>
<li>the pool forces exit before the native crash floor;</li>
<li>recovery is budgeted from the space above this line;</li>
<li>the configured value must satisfy the runtime’s batch-safety invariant.</li>
</ul>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>used KV       ordinary headroom       soft-to-hard reserve      hard floor
█████████████████████████████████████░░░░░░░░░░░░░░░░░░░░░░░░░│
                                      ↑                         ↑
                                  soft limit                hard limit
</code></pre></div><blockquote>
<p><strong>Soft says “finish the work”. Hard says “you may not continue the work, but space was reserved to save what you found”.</strong></p>
</blockquote>
<h2 id="raising-softlimit-does-not-reduce-recovery-to-zero">Raising <code>softLimit</code> does not reduce recovery to zero</h2>
<p>Recovery uses:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>remaining - hardLimit
</code></pre></div><p>not only:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>remaining - softLimit
</code></pre></div><p>Raising <code>softLimit</code> nudges earlier. It does not remove the reserved recovery band down to <code>hardLimit</code>.</p>
<hr/>
<h1 id="4-the-pool-decision-cycle">4. The pool decision cycle</h1>
<h2 id="the-pools-decision-cycle">The pool’s decision cycle</h2>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>SPAWN + EXTEND
      ↓
PRODUCE
      ↓
COMMIT
      ↓
DRAIN
      ↓
SETTLE
      ↓
DISPATCH
</code></pre></div><h3 id="spawn-extend">SPAWN + EXTEND</h3>
<ul>
<li>admit queued Agents if they fit;</li>
<li>extend a shared spine for sequential workflows;</li>
<li>apply pending per-Agent cancellation.</li>
</ul>
<h3 id="produce">PRODUCE</h3>
<ul>
<li>freeze a pressure snapshot;</li>
<li>ask policy whether an Agent must exit before generation;</li>
<li>sample one token for every active branch;</li>
<li>parse stop boundaries and Tool calls;</li>
<li>ask <code>onProduced()</code> what the output means.</li>
</ul>
<h3 id="commit">COMMIT</h3>
<ul>
<li>commit the sampled cohort through BranchStore.</li>
</ul>
<h3 id="drain">DRAIN</h3>
<ul>
<li>receive completed off-loop Tool executions;</li>
<li>return their post-processing to the single native loop.</li>
</ul>
<h3 id="settle">SETTLE</h3>
<ul>
<li>decide whether Tool results and recovery turns fit;</li>
<li>defer oversized ordinary work;</li>
<li>consult <code>onSettleReject()</code> when waiting cannot resolve the deferral;</li>
<li>batch prefill and reactivate admitted Agents.</li>
</ul>
<h3 id="dispatch">DISPATCH</h3>
<ul>
<li>ask <code>shouldExplore()</code> how content-boundary Tools should score;</li>
<li>run declarative guards;</li>
<li>execute Tool calls;</li>
<li>park or fail transient errors.</li>
</ul>
<p>Policy is consulted at specific decision boundaries. It does not control the loop.</p>

<h2 id="onproduced-interpret-the-models-stop"><code>onProduced</code>: interpret the model’s stop</h2>

</code></pre></div><p>Typical decisions:</p>
<ul>
<li>dispatch a valid non-terminal Tool call;</li>
<li>intercept the designated terminal Tool and extract its result;</li>
<li>reject a repeated or unauthorised call with a nudge;</li>
<li>accept free text for a role whose prose is its result;</li>
<li>stop an Agent that reached a budget boundary.</li>
</ul>
<h3 id="terminal-tools-are-result-contracts">Terminal Tools are result contracts</h3>
<p>A pool may designate a terminal Tool:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="nx">agentPool</span><span class="p">({</span>
<span class="w">  </span><span class="nx">terminal</span><span class="o">:</span><span class="w"> </span><span class="kt">reportTool</span><span class="p">,</span>
<span class="w">  </span><span class="c1">// ...</span>
<span class="p">});</span>
</code></pre></div><p>When the model calls it, the framework intercepts the call instead of executing it as an ordinary external action.</p>
<p>The terminal Tool defines:</p>
<ul>
<li>the schema of a valid Agent result;</li>
<li>the point at which the Agent is complete;</li>
<li>the grammar used to force a recovery report.</li>
</ul>
<p>The Tool can be named <code>report</code>, <code>submit</code>, <code>finish</code>, or another harness-specific term.</p>
<hr/>
<h2 id="tool-guards-are-policy-not-execution">Tool guards are policy, not execution</h2>
<p>A Tool defines what an action is and how it runs.</p>
<p>A <code>ToolGuard</code> decides whether a particular call is acceptable now:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="kd">interface</span><span class="w"> </span><span class="nx">ToolGuard</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="nx">args</span><span class="p">,</span>
<span class="w">    </span><span class="nx">lineageHistory</span><span class="p">,</span>
<span class="w">    </span><span class="nx">agent</span><span class="p">,</span>
<span class="w">    </span><span class="nx">toolName</span><span class="p">,</span>
<span class="w">    </span><span class="nx">config</span><span class="p">,</span>

<span class="p">}</span>
</code></pre></div><p>Common guards include:</p>
<ul>
<li>deny protected Tools without a Session grant;</li>
<li>prevent duplicate fetches of the same URL;</li>
<li>prevent repeated identical searches.</li>
</ul>
<p>A rejected call becomes a nudge so the model can pivot.</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>Tool
    execution semantics

    declares authorisation requirement

GrantStore
    holds consent

    decide whether this call may proceed now

    enforces the decision
</code></pre></div><p>Credentials do not need to enter the model context.</p>
<hr/>
<h2 id="exploration-and-lifecycle-are-separate-axes">Exploration and lifecycle are separate axes</h2>
<p><code>shouldExplore()</code> adapts retrieval strategy while the Agent remains active.</p>
<h3 id="explore">Explore</h3>
<p>When context and time are plentiful:</p>
<ul>
<li>favour the Agent’s local task;</li>
<li>broaden coverage;</li>
<li>admit novel evidence;</li>
<li>tolerate landscape discovery.</li>
</ul>
<h3 id="exploit">Exploit</h3>
<p>As resources tighten:</p>
<ul>
<li>enforce coherence with the original root intent;</li>
<li>rank more strictly;</li>
<li>avoid low-value tangents;</li>
<li>turn existing evidence into a result.</li>
</ul>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>explore ───────────────────────────────→ exploit
</code></pre></div><p>Lifecycle remains separate:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>work ─────────────→ report ────────────→ recover or prune
</code></pre></div><p>Do not treat exploit mode as an exit signal.</p>
<hr/>
<h2 id="shouldexit-stop-before-another-token"><code>shouldExit</code>: stop before another token</h2>
<p><code>shouldExit(agent, pressure)</code> runs before <code>produceSync()</code>.</p>
<p>It asks:</p>
<blockquote>
<p>Is it unsafe or no longer worthwhile for this Agent to generate another token?</p>
</blockquote>
<p>The default fallback is effectively:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="k">return</span><span class="w"> </span><span class="nx">pressure</span><span class="p">.</span><span class="nx">critical</span><span class="p">;</span>
</code></pre></div><p>A custom policy may also consider:</p>
<ul>
<li>elapsed hard time;</li>
<li>hard cost budget;</li>
<li>domain completion state;</li>
<li>a harness-specific stop condition.</li>
</ul>
<p>When it returns <code>true</code>:</p>
<ul>
<li>the Agent stops;</li>
<li>its branch remains temporarily available;</li>
<li>the pool may call <code>onRecovery()</code>;</li>
<li>policy does not prune the branch itself.</li>
</ul>
<hr/>
<h2 id="onsettlereject-when-a-result-cannot-fit"><code>onSettleReject</code>: when a result cannot fit</h2>
<p>A Tool may return a result that cannot be admitted while preserving the soft reserve.</p>
<p>The pool first defers it:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>result does not fit
        ↓
wait for siblings to complete and prune
        ↓
retry on a later tick
</code></pre></div><p>This often resolves naturally.</p>
<p><code>onSettleReject()</code> handles the stall-break case:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>deferred work remains
        +
no active sibling can free space
        ↓
waiting cannot change the outcome
</code></pre></div><p>Policy may return a compact nudge:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="p">{</span>
<span class="w">  </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"nudge"</span><span class="p">,</span>
<span class="w">  </span><span class="nx">message</span><span class="o">:</span><span class="w"> </span><span class="s2">"The result is too large. Report from the evidence already gathered."</span>
<span class="p">}</span>
</code></pre></div><p>Or stop the Agent:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="p">{</span>
<span class="w">  </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"idle"</span><span class="p">,</span>
<span class="w">  </span><span class="nx">reason</span><span class="o">:</span><span class="w"> </span><span class="s2">"pressure_settle_reject"</span>
<span class="p">}</span>
</code></pre></div><p>The pool still owns admission and branch lifecycle.</p>
<hr/>
<h2 id="transient-tool-failure-park-retry-or-pivot">Transient Tool failure: park, retry, or pivot</h2>
<p>A Tool may throw <code>ToolRetryError</code> for a transient condition.</p>
<p><code>onToolRetry()</code> returns:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="kr">type</span><span class="w"> </span><span class="nx">ToolRetryAction</span><span class="w"> </span><span class="o">=</span>
<span class="w">  </span><span class="o">|</span><span class="w"> </span><span class="p">{</span><span class="w"> </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"retry"</span><span class="p">;</span><span class="w"> </span><span class="nx">afterMs?</span><span class="o">:</span><span class="w"> </span><span class="kt">number</span><span class="w"> </span><span class="p">}</span>
<span class="w">  </span><span class="o">|</span><span class="w"> </span><span class="p">{</span><span class="w"> </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"fail"</span><span class="p">;</span><span class="w"> </span><span class="nx">message?</span><span class="o">:</span><span class="w"> </span><span class="kt">string</span><span class="w"> </span><span class="p">};</span>
</code></pre></div><h3 id="retry">Retry</h3>
<p>The Agent parks in <code>awaiting_tool</code>:</p>
<ul>
<li>no generation turns are consumed;</li>
<li>no tokens are produced;</li>
<li>siblings continue;</li>
<li>the same call is retried later.</li>
</ul>
<h3 id="fail">Fail</h3>
<p>The pool settles a compact failure result into the branch so the Agent can choose another route.</p>
<p>A custom policy can consider:</p>
<ul>
<li>retry attempt;</li>
<li>remaining wall time;</li>
<li>Tool importance;</li>
<li>available alternatives.</li>
</ul>
<p>Avoid unbounded retries.</p>
<hr/>
<h1 id="6-recovery">6. Recovery</h1>
<h2 id="recovery-save-useful-work-before-pruning">Recovery: save useful work before pruning</h2>
<p>An Agent may stop without a voluntary terminal result because of:</p>
<ul>
<li>context pressure;</li>
<li>elapsed time;</li>
<li>maximum turns;</li>
<li>graceful wind-down;</li>
<li>a policy hard exit.</li>
</ul>
<p>Its branch may still contain useful evidence.</p>
<p><code>onRecovery()</code> chooses:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="kr">type</span><span class="w"> </span><span class="nx">RecoveryAction</span><span class="w"> </span><span class="o">=</span>
<span class="w">  </span><span class="o">|</span><span class="w"> </span><span class="p">{</span>
<span class="w">      </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"extract"</span><span class="p">;</span>
<span class="w">      </span><span class="nx">prompt</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="nx">system</span><span class="o">:</span><span class="w"> </span><span class="kt">string</span><span class="p">;</span>
<span class="w">        </span><span class="nx">user</span><span class="o">:</span><span class="w"> </span><span class="kt">string</span><span class="p">;</span>
<span class="w">      </span><span class="p">};</span>
<span class="w">    </span><span class="p">}</span>
<span class="w">  </span><span class="o">|</span><span class="w"> </span><span class="p">{</span><span class="w"> </span><span class="kr">type</span><span class="o">:</span><span class="w"> </span><span class="s2">"skip"</span><span class="w"> </span><span class="p">};</span>
</code></pre></div><h3 id="policy-owns-the-meaning">Policy owns the meaning</h3>
<p>Policy decides:</p>
<ul>
<li>whether the work is worth extracting;</li>
<li>how to instruct the Agent to compress it;</li>
<li>whether recovery should be staggered or parallel;</li>
<li>an optional preferred report budget.</li>
</ul>
<h3 id="agentpool-owns-the-mechanics">AgentPool owns the mechanics</h3>
<p>The pool:</p>
<ul>
<li>computes what safely fits;</li>
<li>forces the terminal Tool grammar;</li>
<li>prefills the recovery turn;</li>
<li>applies a token stop where bounded;</li>
<li>parses the terminal result;</li>
<li>salvages truncated output where possible;</li>
<li>emits recovery events;</li>
<li>prunes the branch.</li>
</ul>
<blockquote>
<p><strong>Policy asks for the report. The pool guarantees that asking is mechanically safe.</strong></p>
</blockquote>
<h3 id="recovery-is-a-real-turn">Recovery is a real turn</h3>
<p>Recovery is not string extraction from hidden state.</p>
<p>The pool injects a final instruction into the Agent’s live branch and constrains generation to the terminal result contract.</p>
<hr/>
<h2 id="why-recovery-uses-the-hard-limit-reserve">Why recovery uses the hard-limit reserve</h2>
<p>Near the soft boundary:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>remaining ≈ softLimit
</code></pre></div><p>there may be almost no ordinary headroom:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>headroom = remaining - softLimit ≈ 0
</code></pre></div><p>If recovery were budgeted only from <code>headroom</code>, the system would be unable to report exactly when reporting is required.</p>
<p>Instead:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>recovery capacity = remaining - hardLimit
</code></pre></div><p>The band between soft and hard limits is available for safely converting unfinished work into a result.</p>
<p>The soft boundary means:</p>
<blockquote>
<p>Stop opening ordinary work.</p>
</blockquote>
<p>It does not mean:</p>
<blockquote>
<p>No more recovery tokens may be decoded.</p>
</blockquote>
<hr/>
<h2 id="staggered-and-parallel-recovery">Staggered and parallel recovery</h2>
<p><code>recoveryShape</code> expresses a product trade-off.</p>
<h3 id="staggered">Staggered</h3>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>recover A
    ↓
prune A
    ↓
recover B
    ↓
prune B
</code></pre></div><p>Properties:</p>
<ul>
<li>one Agent at a time;</li>
<li>each report benefits from earlier pruning;</li>
<li>larger or uncapped reports;</li>
<li>maximum individual finding preservation;</li>
<li>blocks pool progress;</li>
<li>suited to high-effort, quality-first workflows.</li>
</ul>
<h3 id="parallel">Parallel</h3>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>budget the cohort
        ↓
admit recovery turns
        ↓
decode them in the pool loop
        ↓
prune each as it finishes
</code></pre></div><p>Properties:</p>
<ul>
<li>reports share recovery capacity;</li>
<li>report sizes are mechanically bounded;</li>
<li>better batching and latency;</li>
<li>suited to low/medium effort and graceful wind-down.</li>
</ul>
<p>An explicit <code>reportBudget</code> is a preference. The pool clamps it to what safely fits.</p>
<hr/>
<h2 id="in-flight-terminal-report-salvage">In-flight terminal-report salvage</h2>
<p>If an Agent is force-stopped while already emitting its terminal Tool call, restarting recovery would:</p>
<ol>
<li>discard the partial report;</li>
<li>inject another turn;</li>
<li>consume additional KV;</li>
<li>risk failing again in the same exhausted context.</li>
</ol>
<p>The pool instead parses and salvages the existing partial terminal output without further decode.</p>
<p>This is a pool mechanic, not a policy hook.</p>
<p>Policy decides that the Agent should stop. The pool chooses the least-destructive safe route.</p>
<hr/>
<h2 id="wind-down-per-agent-cancellation-and-scope-halt">Wind-down, per-Agent cancellation, and scope halt</h2>
<p>These controls have different meanings.</p>
<h3 id="graceful-wind-down">Graceful wind-down</h3>
<p>A <code>WindDown</code> signal means:</p>
<blockquote>
<p>Stop expanding, drain in-flight work, and return the best available result.</p>
</blockquote>
<p>The pool:</p>
<ul>
<li>stops new spawns;</li>
<li>allows in-flight Tools to settle;</li>
<li>recovers useful findings;</li>
<li>converges towards completion.</li>
</ul>
<p>This suits a <strong>Wrap up now</strong> action.</p>
<h3 id="per-agent-cancellation">Per-Agent cancellation</h3>
<p>A <code>CancelAgent</code> signal means:</p>
<blockquote>
<p>Discard this one line of work.</p>
</blockquote>
<p>The pool reclaims that Agent while siblings continue.</p>
<p>Depending on the contract, this may deliberately skip recovery.</p>
<h3 id="scope-halt">Scope halt</h3>
<p>A Session release means:</p>
<blockquote>
<p>The query no longer has an owner.</p>
</blockquote>
<p>Effection unwinds the entire child tree.</p>
<p>A user asking to wrap up is not the same event as a browser disappearing.</p>
<hr/>
<h1 id="7-configuration-and-extension">7. Configuration and extension</h1>
<h2 id="configuring-the-default-policy">Configuring the default policy</h2>
<p>Most harnesses should configure <code>DefaultAgentPolicy</code> rather than implement the entire interface.</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="kd">const</span><span class="w"> </span><span class="nx">policy</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="ow">new</span><span class="w"> </span><span class="nx">DefaultAgentPolicy</span><span class="p">({</span>
<span class="w">  </span><span class="nx">terminalToolName</span><span class="o">:</span><span class="w"> </span><span class="s2">"report"</span><span class="p">,</span>

<span class="w">  </span><span class="nx">minToolCallsBeforeReturn</span><span class="o">:</span><span class="w"> </span><span class="kt">2</span><span class="p">,</span>

<span class="w">  </span><span class="nx">shouldExplore</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nx">context</span><span class="o">:</span><span class="w"> </span><span class="kt">0.4</span><span class="p">,</span>
<span class="w">    </span><span class="nx">time</span><span class="o">:</span><span class="w"> </span><span class="kt">0.5</span><span class="p">,</span>
<span class="w">  </span><span class="p">},</span>

<span class="w">  </span><span class="nx">budget</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nx">context</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">      </span><span class="nx">softLimit</span><span class="o">:</span><span class="w"> </span><span class="kt">2048</span><span class="p">,</span>
<span class="w">      </span><span class="nx">hardLimit</span><span class="o">:</span><span class="w"> </span><span class="kt">512</span><span class="p">,</span>
<span class="w">    </span><span class="p">},</span>
<span class="w">    </span><span class="nx">time</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">      </span><span class="nx">softLimit</span><span class="o">:</span><span class="w"> </span><span class="kt">90_000</span><span class="p">,</span>
<span class="w">      </span><span class="nx">hardLimit</span><span class="o">:</span><span class="w"> </span><span class="kt">120_000</span><span class="p">,</span>
<span class="w">    </span><span class="p">},</span>
<span class="w">  </span><span class="p">},</span>

<span class="w">  </span><span class="nx">recovery</span><span class="o">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nx">system</span><span class="o">:</span><span class="w"> </span><span class="s2">"Return the strongest findings already established."</span><span class="p">,</span>
<span class="w">    </span><span class="nx">user</span><span class="o">:</span><span class="w"> </span><span class="s2">"Produce a concise evidence-backed report."</span><span class="p">,</span>
<span class="w">  </span><span class="p">},</span>

<span class="w">  </span><span class="nx">recoveryShape</span><span class="o">:</span><span class="w"> </span><span class="s2">"parallel"</span><span class="p">,</span>
<span class="w">  </span><span class="nx">reportBudget</span><span class="o">:</span><span class="w"> </span><span class="kt">768</span><span class="p">,</span>

<span class="w">  </span><span class="nx">maxToolRetries</span><span class="o">:</span><span class="w"> </span><span class="kt">1</span><span class="p">,</span>
<span class="p">});</span>
</code></pre></div><p>Interpretation:</p>
<ul>
<li>retrieval becomes more exploitative as context or time tightens;</li>
<li>soft boundaries encourage completion;</li>
<li>hard boundaries force exit;</li>
<li>stopped Agents may recover;</li>
<li>parallel recovery bounds latency and report size.</li>
</ul>
<p>Tune the policy to the workload, not merely to the model.</p>

<h2 id="a-worked-pressure-example">A worked pressure example</h2>
<p>Assume:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>nCtx      = 32,768
softLimit = 2,048
hardLimit =   512
cellsUsed = 29,500
</code></pre></div><p>Then:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>remaining = 3,268
headroom  = 1,220
critical  = false
</code></pre></div><p>Ordinary work still has approximately 1,220 cells above the soft reserve.</p>
<p>Later:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>cellsUsed = 30,900
remaining = 1,868
headroom  =  -180
critical  = false
</code></pre></div><p>The soft boundary is crossed:</p>
<ul>
<li>stop opening research;</li>
<li>defer oversized ordinary results;</li>
<li>nudge towards reporting;</li>
<li>recovery still has up to <code>1,868 - 512 = 1,356</code> cells above the hard line.</li>
</ul>
<p>Later:</p>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>cellsUsed = 32,300
remaining = 468
critical  = true
</code></pre></div><p>An ordinary Agent must not produce another token.</p>
<p>The pool stops it before decode and applies salvage or recovery.</p>
<blockquote>
<p><code>headroom &lt;= 0</code> and <code>critical === true</code> are not the same state.</p>
</blockquote>

<h2 id="writing-a-custom-policy">Writing a custom policy</h2>
<p>Custom policy is appropriate when the harness has domain rules that configuration cannot express.</p>
<p>Prefer extending the default:</p>
<div class="code-frame"><div class="code-label">TypeScript</div><pre><code><span class="kd">class</span><span class="w"> </span><span class="nx">CaseworkPolicy</span><span class="w"> </span><span class="k">extends</span><span class="w"> </span><span class="nx">DefaultAgentPolicy</span><span class="w"> </span><span class="p">{</span>
<span class="w">  </span><span class="kd">override</span><span class="w"> </span><span class="nx">shouldExplore</span><span class="p">(</span>
<span class="w">    </span><span class="nx">agent</span><span class="o">:</span><span class="w"> </span><span class="kt">Agent</span><span class="p">,</span>
<span class="w">    </span><span class="nx">pressure</span><span class="o">:</span><span class="w"> </span><span class="kt">ContextPressure</span><span class="p">,</span>
<span class="w">  </span><span class="p">)</span><span class="o">:</span><span class="w"> </span><span class="kt">boolean</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="nx">hasUnresolvedMandatoryIssue</span><span class="p">(</span><span class="nx">agent</span><span class="p">))</span><span class="w"> </span><span class="p">{</span>
<span class="w">      </span><span class="k">return</span><span class="w"> </span><span class="kc">true</span><span class="p">;</span>
<span class="w">    </span><span class="p">}</span>

<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="k">super</span><span class="p">.</span><span class="nx">shouldExplore</span><span class="p">(</span><span class="nx">agent</span><span class="p">,</span><span class="w"> </span><span class="nx">pressure</span><span class="p">);</span>
<span class="w">  </span><span class="p">}</span>

<span class="w">  </span><span class="kd">override</span><span class="w"> </span><span class="nx">shouldExit</span><span class="p">(</span>
<span class="w">    </span><span class="nx">agent</span><span class="o">:</span><span class="w"> </span><span class="kt">Agent</span><span class="p">,</span>
<span class="w">    </span><span class="nx">pressure</span><span class="o">:</span><span class="w"> </span><span class="kt">ContextPressure</span><span class="p">,</span>
<span class="w">  </span><span class="p">)</span><span class="o">:</span><span class="w"> </span><span class="kt">boolean</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="nx">caseDeadlineHasPassed</span><span class="p">())</span><span class="w"> </span><span class="p">{</span>
<span class="w">      </span><span class="k">return</span><span class="w"> </span><span class="kc">true</span><span class="p">;</span>
<span class="w">    </span><span class="p">}</span>

<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="k">super</span><span class="p">.</span><span class="nx">shouldExit</span><span class="p">(</span><span class="nx">agent</span><span class="p">,</span><span class="w"> </span><span class="nx">pressure</span><span class="p">);</span>
<span class="w">  </span><span class="p">}</span>
<span class="p">}</span>
</code></pre></div><p>This preserves default handling for:</p>
<ul>
<li>terminal Tools;</li>
<li>authorisation and dedup guards;</li>
<li>recovery;</li>
<li>pressure safety;</li>
<li>retries.</li>
</ul>
<h3 id="override-decisions-not-execution">Override decisions, not execution</h3>
<p>A policy should return actions.</p>
<p>It should not:</p>
<ul>
<li>call native decode;</li>
<li>mutate BranchStore;</li>
<li>prune branches;</li>
<li>execute Tools;</li>
<li>create asynchronous side effects inside hooks;</li>
<li>maintain a second scheduler.</li>
</ul>
<p>If a decision requires substantial asynchronous work, it probably belongs in:</p>
<ul>
<li>an orchestrator;</li>
<li>a Tool;</li>
<li>a Source;</li>
<li>or another scoped Operation.</li>
</ul>

<span class="w">  </span><span class="kd">override</span><span class="w"> </span><span class="nx">onProduced</span><span class="p">(</span>

<h2 id="tuning-by-workload">Tuning by workload</h2>
<h3 id="interactive-assistant">Interactive assistant</h3>
<p>Prefer:</p>
<ul>
<li>fewer Agents;</li>
<li>earlier exploit;</li>
<li>tighter time limits;</li>
<li>parallel recovery;</li>
<li>modest report budgets;</li>
<li>low retry count.</li>
</ul>
<h3 id="broad-research">Broad research</h3>
<p>Prefer:</p>
<ul>
<li>exploration while context is healthy;</li>
<li>enough soft reserve for synthesis;</li>
<li><code>pruneOnReturn</code>;</li>
<li>terminal Tool contracts;</li>
<li>parallel recovery for lower effort levels.</li>
</ul>
<h3 id="deep-research">Deep research</h3>
<p>Prefer:</p>
<ul>
<li>dynamic orchestration;</li>
<li>larger context;</li>
<li>later exploit thresholds;</li>
<li>staggered recovery;</li>
<li>generous hard time;</li>
<li>explicit downstream synthesis reserve.</li>
</ul>
<h3 id="casework">Casework</h3>
<p>Prefer:</p>
<ul>
<li>policy guards for institutional rules;</li>
<li>domain-specific exit conditions;</li>
<li>recoverable intermediate findings;</li>
<li>protected action Tools;</li>
<li>grants and audit events;</li>
<li>procedural orchestration.</li>
</ul>
<p>Policy should reflect the product’s meaning of <strong>done</strong>.</p>

<h1 id="quick-reference">Quick reference</h1>
<h2 id="common-mistakes">Common mistakes</h2>
<h3 id="treating-the-soft-limit-as-a-kill-line">Treating the soft limit as a kill line</h3>
<p>It is the new-work and nudge boundary. Recovery may use the reserve down to the hard limit.</p>
<h3 id="raising-the-soft-limit-to-get-longer-recovery">Raising the soft limit to get longer recovery</h3>
<p>That nudges earlier. Recovery remains bounded by the hard-limit reserve and current cohort.</p>
<h3 id="making-policy-prune-branches">Making policy prune branches</h3>
<p>Policy returns decisions. AgentPool owns branch lifecycle.</p>
<h3 id="performing-async-work-inside-hooks">Performing async work inside hooks</h3>
<p>Hooks are decision boundaries. Move asynchronous work into an orchestrator, Tool, Source, or Operation.</p>
<h3 id="conflating-exploit-with-exit">Conflating exploit with exit</h3>
<p><code>shouldExplore() === false</code> narrows retrieval. It does not end the Agent.</p>
<h3 id="retrying-without-considering-time">Retrying without considering time</h3>
<p>A retry that cannot finish inside the useful time budget should fail or pivot.</p>
<h3 id="using-session-halt-for-wrap-up">Using Session halt for wrap-up</h3>
<p>A halt removes the owner. Use graceful wind-down when the user wants the best available result.</p>
<h3 id="treating-policy-as-a-native-safety-escape-hatch">Treating policy as a native-safety escape hatch</h3>
<p>The pool validates hard invariants. Policy cannot opt out of runtime safety.</p>

<h2 id="rules-for-coding-agents">Rules for coding agents</h2>
<div class="code-frame"><div class="code-label">Markdown</div><pre><code><span class="gu">## Lloyal AgentPolicy invariants</span>

<span class="k">-</span><span class="w"> </span>AgentPolicy is a synchronous decision strategy, not a scheduler.
<span class="k">-</span><span class="w"> </span>BranchStore accounts, ContextPressure observes, policy decides, and
  AgentPool enforces.
<span class="k">-</span><span class="w"> </span>Do not mutate branches, prune KV, or call native decode from a policy hook.
<span class="k">-</span><span class="w"> </span>Treat ContextPressure as an immutable decision-boundary snapshot.
<span class="k">-</span><span class="w"> </span><span class="sb">\`softLimit\`</span> is the new-work and nudge boundary.
<span class="k">-</span><span class="w"> </span><span class="sb">\`hardLimit\`</span> is the mechanical decode floor and recovery boundary.
<span class="k">-</span><span class="w"> </span>Recovery budgets from <span class="sb">\`remaining - hardLimit\`</span>, not only from <span class="sb">\`headroom\`</span>.
<span class="k">-</span><span class="w"> </span><span class="sb">\`shouldExplore\`</span> changes retrieval strategy; it does not terminate an Agent.
<span class="k">-</span><span class="w"> </span><span class="sb">\`shouldExit\`</span> stops an Agent but leaves its branch available for recovery.
<span class="k">-</span><span class="w"> </span><span class="sb">\`onRecovery\`</span> chooses extract or skip; AgentPool enforces grammar and budget.
<span class="k">-</span><span class="w"> </span><span class="sb">\`onSettleReject\`</span> is a stall-break after ordinary deferral cannot resolve.
<span class="k">-</span><span class="w"> </span>Wind-down, per-Agent cancellation, and Effection scope halt are different.
<span class="k">-</span><span class="w"> </span>Prefer configuring or extending <span class="sb">\`DefaultAgentPolicy\`</span> over replacing it.
</code></pre></div><hr/>
<h1 id="relationship-to-the-programming-model">Relationship to the programming model</h1>
<p>Structured concurrency answers:</p>
<blockquote>
<p>Who owns this work, and what happens when its owner ends?</p>
</blockquote>
<p>AgentPolicy answers:</p>
<blockquote>
<p>While the owner and AgentPool remain alive, what should this Agent do next?</p>
</blockquote>
<div class="code-frame"><div class="code-label">Structure</div><pre><code>Effection scope
    owns the pool
        ↓
AgentPool
    owns Agent execution and BranchStore mechanics
        ↓
ContextPressure
    presents stable resource facts
        ↓
AgentPolicy
    returns behavioural decisions
        ↓
AgentPool
    safely applies them
</code></pre></div><p>That separation allows harness developers to customise judgement under scarcity without rewriting lifecycle management or inference scheduling.</p>
